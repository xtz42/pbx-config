# Плейсхолдеры и открытые вопросы

Здесь перечислено всё, что в репозитории заполнено выдуманными значениями
или требует решения. Реальные данные компании в репозиторий не вносятся:
в проде они попадают в инвентарь `inventory/prod/` и Ansible Vault.

## Плейсхолдеры (заменить при подготовке прода)

| Где | Что сейчас | Что нужно |
|-----|------------|-----------|
| `CODEOWNERS` | `@CHANGE_ME_*` | реальные группы/пользователи GitLab |
| `tenants/*.yml` → `dids` | синтетические `7000000000x` | реальные DID тенанта (только в прод-инвентаре или Vault — решить) |
| `tenants/*.yml` → `sip_domain` | `<код>.pbx.test` | домен регистрации операторов (WebRTC/WSS) |
| `tenants/*.yml` → `recordings.smb_share` | `//smb.example.test/...` | реальная SMB-папка записей тенанта, учётная запись — в Vault |
| `inventory/prod/` | будет создан с плейсхолдерами | адреса, имена серверов, BGP-адрес SBC |
| Транк провайдера (Kcell) | на стенде — SIPp/софтфон | адреса сигнализации/медиа, кодеки, формат номера (E.164 или нет) |
| TLS для WSS | на стенде — самоподписанный сертификат | сертификат для домена операторов |
| `sounds/tenants/bii/*/welcome.wav` | синтезированная речь (espeak-ng) | студийные записи приветствий |
| Репозиторий RPM для прода (`rpm_source: repo`) | не задан | внутренний репозиторий dnf и процесс публикации пакетов |

## Открытые вопросы (решаются с владельцем проекта до соответствующего этапа)

1. ~~Поставка rtpengine для AlmaLinux 9~~ — **решено (этап 2)**: свой RPM
   по официальному spec, без транскодирования и модуля ядра (`rpm/rtpengine.spec`).
2. **Источник учётных данных операторов для Kamailio** (этап 3):
   Kamailio — регистратор, а операторы заведены в базе тенанта (PJSIP realtime).
   Варианты: Kamailio читает представление в базе тенанта / отдельная
   общая таблица подписчиков с доменом тенанта.
3. **Хранение реальных DID**: в `tenants/*.yml` (они не секретны,
   но это данные компании) или в прод-инвентаре.
4. **Формат номера от провайдера** (DID в R-URI): сейчас Kamailio только
   убирает «+» (`route[NORMALIZE_DID]`), DID в `tenants/*.yml` — 11 цифр.
5. **Сегмент для WebRTC операторов** (этап 3): на каком адресе Kamailio
   слушает WSS — voice-edge, voice-core или отдельная сеть офиса.
6. **Репозиторий**: сейчас удалённый репозиторий — GitHub (рабочая копия
   для разработки), целевой — приватный проект на gitlab.com.
   Шаблон MR лежит в `docs/templates/merge_request.md`; GitLab подхватывает
   шаблоны только из `.gitlab/merge_request_templates/` — при переносе
   на GitLab скопировать туда (или перенести, если удобнее).
