# ADR 0001. AlmaLinux 9, Asterisk 22 LTS, Kamailio и rtpengine

- **Статус:** Принято
- **Дата:** 2026-11-27
- **Задача:** NET-475

## Контекст

Колл-центр работает на Oktell — проприетарной платформе под Windows.
Нужно перейти на свободное ПО без лицензионных платежей, с конфигурацией,
которую можно хранить в Git и раскатывать автоматически.
Компания обслуживает несколько тенантов (юрлиц), звонки которых не должны
пересекаться. Провайдер подключается SIP-транком; операторы работают
из браузера (WebRTC).

## Решение

1. **ОС всех серверов — AlmaLinux 9.** Бесплатный двоичный аналог RHEL 9,
   поддержка до 2032 года, привычный для команды стек (dnf, SELinux, firewalld).
2. **Asterisk 22 LTS, собранный из исходников, в виде собственного RPM.**
   Spec-файл лежит в `rpm/asterisk.spec`. Собираем сами, потому что
   в штатных репозиториях AlmaLinux 9 / EPEL нет пакета нужной LTS-ветки
   с нужным набором модулей (PJSIP, ODBC realtime, `app_queue`, WebRTC).
   Свой RPM даёт воспроизводимую сборку, одинаковую на стенде и в проде.
3. **SBC на краю сети — Kamailio + rtpengine**, общий для всех тенантов.
   - Kamailio: приём транка провайдера, маршрутизация DID → пара Asterisk
     тенанта (модуль `dispatcher`, алгоритм 8 — по приоритету, ЦОД 1 первым),
     проверка доступности SIP OPTIONS, `failure_route` с `ds_next_dst()`;
     регистратор операторов (WebRTC через WSS), регистрации хранятся в БД;
     Asterisk звонит операторам через Kamailio.
   - rtpengine: медиа-прокси с двумя интерфейсами — внешним (voice-edge)
     и внутренним (voice-core); мост WebRTC (DTLS-SRTP, ICE) ↔ RTP.
   - В проде — пара SBC в ЦОД 1 и ЦОД 2 на общем BGP-адресе.

## Рассмотренные альтернативы

- **Остаться на Oktell.** Лицензии, Windows, нет управления конфигурацией через Git.
- **FreeSWITCH (+ FusionPBX).** Сильная платформа, но у команды больше
  опыта с Asterisk; `app_queue`, queue_log и realtime-очереди Asterisk
  ближе к отчётам, которые сейчас строятся по Oktell.
- **Asterisk на краю сети без SBC.** Публичный SIP прямо на АТС тенанта,
  отдельные адреса на каждый тенант, нет единой точки для WebRTC
  и защиты от сканеров; отказоустойчивость пришлось бы решать на каждой паре.
- **Готовые пакеты Asterisk из сторонних репозиториев.** Нет контроля над
  версией и набором модулей, зависимость от чужого графика обновлений.
- **Debian/Ubuntu.** Технически подходит, но стандарт компании для серверов — RHEL-совместимые ОС.

## Последствия

- Нужен конвейер сборки RPM Asterisk (spec в Git; сборка — на этапе 2,
  выпуск пакета в собственный репозиторий — позже).
- Kamailio ставится из официального репозитория Kamailio для RHEL 9.
  Способ поставки rtpengine для EL9 (сборка из исходников или сторонний
  репозиторий) нужно выбрать отдельно — см. `docs/placeholders.md`.
- Обновления Asterisk в пределах ветки 22 — пересборка RPM и раскатка
  Ansible; переход на следующую LTS — отдельный ADR.
- SBC — общая точка отказа для всех тенантов, поэтому он резервируется
  парой в двух ЦОД.
